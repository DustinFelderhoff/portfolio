## Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| **Shared CSS FOUC (Flash of Unstyled Content)** | Low | CSS loads in `<head>` before any body content. The `<link>` tag is synchronous — browser blocks rendering until CSS is downloaded. Risk is near-zero for a ~15KB stylesheet on GH Pages. |
| **deploy_ai_news.py nav template breakage** | Low | Only the HEAD nav template needs Apply removed. CSS template stays untouched. Verify with `grep -n "apply" deploy_ai_news.py` after edit — only the one line should be gone. |
| **Bottom-nav differences between index.html and sub-pages** | Low (pre-existing) | Sub-pages use file links (`about.html`, `projects.html`) while index uses anchor links (`#about`, `#projects`). This is by design. Do NOT normalize them. |
| **E2E tests fail until deploy** | High | Tests hit production URL. Two options: (a) deploy first then test, (b) temporarily change test URLs to `file://` paths for pre-deploy validation. Documented in Phase 5. |
| **Relative path mismatch on styles.css** | Low | All 6 modified pages are in repo root — `href="styles.css"` works everywhere. case-studies/ page is NOT modified. ai-news pages keep inline CSS. |
| **Apply page deletion breaks local tooling** | Medium | Check `grep -rn "apply/index" --include="*.py" --include="*.sh" --include="*.bat" .` first. If local job-tracker tooling reads this path, use placeholder instead of delete. |
| **No CI/CD — direct push to production** | Medium | All changes must be verified locally before `git add` and `git push`. Set up a local HTTP server (`python -m http.server`) and preview before committing. |
