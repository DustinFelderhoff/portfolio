Problem

A family story-sharing app sends one prompt per day to each family member. The initial MVP used a basic algorithm: exclude seen prompts, balance categories, prioritize personal prompts. Users reported prompts felt repetitive and didn't account for real life events like birthdays, new family members, anniversaries, or family milestones. Different generations also seemed to prefer different prompt styles.

Process

Researched how major platforms solve the "what to show next" problem:

🎬 Netflix

Multi-layer personalization. 75% of watched content comes from recommendations. Key insight: personalize the order, not just the content.

🦉 Duolingo

Half-Life Regression + Thompson Sampling bandits for lesson sequencing. Key insight: optimal intervals are learner-specific.

📝 Anki/SuperMemo

SM-2 algorithm with ease factors. FSRS: three memory states (Difficulty, Stability, Retrievability). Key insight: space reviews just before forgetting.

🎵 Spotify

Collaborative filtering + audio analysis + bandit algorithms for playlist continuation. Key insight: combine explicit + implicit signals.

📌 Pinterest

Pixie random-walk recommendation for 3B+ items. Key insight: graph-based discovery works for sparse data.

📊 Competitors

StoryWorth (curated queue), Remento (AI-curated from family tree), 1000 Questions (static list), Life Stories (chronological arc).

Algorithm Candidates

OptionApproachKey Insight
A: EOSRSWeighted scoring: category freshness + emotional valence + specificity + time-of-day + SRS skip cooldownBlends Netflix personalization + Duolingo SRS + Anki skip intervals
B: Thompson SamplingBayesian bandit that learns per-category answer ratesAuto-explores new prompts while exploiting known winners
C: Per-User CalibrationPersonalized weights adapting per user behaviorMost personalized but upfront data needed

User Feedback → Architecture Pivot

User rejected "pick one." Proposed running both algorithms simultaneously as a dual-track A/B test. Different generations may prefer different approaches, so let the data decide.

Final Architecture:

Layer 1: Life Event Override 🔔
Checks for birthdays, new family members, milestone recordings, anniversaries, re-engagement. If any trigger fires, that prompt wins immediately. Zero LLM cost. Just date-based SQL queries.
Layer 2: Dual-Track A/B
Users randomly assigned to Track A (EOSRS) or Track B (Thompson Sampling). Answer rates compared weekly. Whichever wins becomes default for that segment.
Layer 3: MVP Fallback
Safety net: exclude seen-IDs + category round-robin. Rarely triggers.
